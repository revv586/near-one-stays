# NEAR ONE · ที่พักใกล้ One Bangkok

เว็บภาษาไทยสำหรับเปรียบเทียบหอพัก อพาร์ตเมนต์ และคอนโดตามข้อมูลในแชท พร้อมหน้ารายละเอียด รูปจากประกาศต้นทาง และลิงก์อ้างอิง

## เปิดใช้งานบน Mac

1. แตก ZIP แล้วดับเบิลคลิก `Install-on-Desktop.command` โปรเจกต์จะอยู่ที่ `~/Desktop/near-one-stays` หากมีโฟลเดอร์เดิมจะสร้างชื่อใหม่แทนการทับ
2. ต้องมี Node.js 20+ และ Python 3.10+ (ไม่มีแพ็กเกจเพิ่มเติมที่ต้องติดตั้ง)
3. ดับเบิลคลิก `Start.command` แล้วเปิด http://localhost:4173 คงหน้าต่าง Terminal นี้ไว้ระหว่างใช้งาน
4. หาก macOS ไม่อนุญาตเปิดไฟล์ ให้คลิกขวา > Open ตามการตั้งค่าความปลอดภัยของเครื่อง

หรือเปิด Terminal ในโฟลเดอร์แล้วรัน:

```
npm start
```

## สิ่งที่ทำได้

- เลื่อนงบ 2,500–15,000 บาท กรองได้ทันที พร้อมเรียงราคาขึ้น/ลง
- กรองชื่อ ย่าน สถานี ประเภทที่พัก สัญญา 1–4 หรือ 6 เดือน ห้องน้ำ และระยะเดินที่ยืนยันแล้ว
- เปิดหน้ารายละเอียดแต่ละที่พัก ลิงก์ต้นทาง แผนที่ ค่าแรกเข้า น้ำไฟ วันที่ผู้ประกาศอัปเดต และวันตรวจเว็บ
- รายการโปรดเก็บใน localStorage ของแต่ละเบราว์เซอร์ ไม่ส่งข้อมูลผู้ใช้ขึ้นเซิร์ฟเวอร์
- เปรียบเทียบสูงสุด 3 ที่พัก
- แยกเบาะแส / แคปซูล / ห้องเต็มหรือเกินเกณฑ์ ไม่มีการอ้างระยะเส้นตรงเป็นระยะเดิน
- มีหน้าข้อมูลและการอัปเดต ดูผลตรวจล้มเหลว ข้อมูลเปลี่ยน และคิวเบาะแสใหม่

## UI และแหล่งค้นหาที่เพิ่ม

- ข้อความหลัก 16–17 px ชื่อการ์ด 21–22 px ปุ่มหลักและหัวใจอย่างน้อย 48 px
- มือถือแสดงการ์ดคอลัมน์เดียว มีปุ่มเปิดตัวกรองเพิ่มเติม
- หน้า `#/sources` รวม 18 แหล่งค้นหา เลือกสถานีเพื่อเปิดค้นประกาศสาธารณะได้
- แยกชัดเจนระหว่างตัวตรวจประกาศที่เก็บไว้ แหล่งค้นพบอัตโนมัติ 2 แพลตฟอร์ม และแหล่งค้นเพิ่มเติมที่ยังต้องตรวจด้วยตนเอง
- รูปใหม่ 82 ภาพมาจาก 41 ที่พักนั้นโดยตรง

## ข้อมูลเริ่มต้นและความถูกต้อง

`dist/data/listings.json` คือฐานข้อมูลหลัก มี 53 ที่พักหลังตรวจหน้าประกาศตรงเพิ่มและตัดชื่อซ้ำแล้ว (รวมเบาะแส ห้องเต็ม และรายการเกินเงื่อนไข ไม่ใช่ 53 ห้องที่ผ่านเกณฑ์) รูปที่มีดึงจากที่พักนั้น ไม่ใช้ภาพ stock แทนรูปห้องจริง รูปอาจไม่ได้ตรงกับห้องที่ว่าง จึงต้องเปิดประกาศต้นทางตรวจอีกครั้ง

ข้อมูลที่พักอ้างอิงการค้นหา 1–6 พฤศจิกายน 2569 ไม่ได้ติดต่อเจ้าของ ไม่มีเส้นทางเดินที่ยืนยันแล้วในชุดเริ่มต้น ฟิลเตอร์ “ยืนยันระยะเดิน” จึงอาจได้ผลลัพธ์ว่าง ซึ่งเป็นพฤติกรรมที่ตั้งใจไว้

**PS House:** หน้า HTML ปัจจุบันระบุห้องไม่มีหน้าต่าง 15 ตร.ม. ชั้น 3 ว่าง 30 พ.ย. ค่าเช่า 5,400 บาท สำหรับ 6 เดือน ส่วนข้อมูลห้อง 20 ตร.ม. 5,900 บาทยังอยู่ในประกาศแต่ไม่ได้ยืนยันวันว่าง ต้องถามเจ้าของอีกครั้ง

อย่าใช้ `scripts/seed.py` หลังปรับข้อมูลจริง เพราะจะรีเซ็ตแค็ตตาล็อกกลับชุดตั้งต้น

## อัปเดตข้อมูลรายชั่วโมง: มี 2 ทางเลือก

### A. ตรวจบน Mac

ดับเบิลคลิก `Enable-hourly-updates.command` เพื่อติดตั้ง LaunchAgent ที่ตรวจทันทีและทุก 3,600 วินาทีเมื่อเครื่องเปิดและออนไลน์ ปิดได้ด้วย `Disable-hourly-updates.command` ตรวจ logs ใน `logs/` เว็บ local อ่าน JSON ใหม่เป็นระยะ ไม่จำเป็นต้อง restart

การตั้งเวลาบน Mac อัปเดตเว็บ local เท่านั้น ไม่ได้อัปโหลดไปยังเว็บที่โฮสต์ให้ดูในแชท

### B. CI/CD บน GitHub Pages (เว็บออนไลน์อัปเดตแม้ปิด Mac)

โปรเจกต์มี `.github/workflows/ci.yml` และ `update-and-deploy.yml` พร้อมใช้งาน **ยังไม่เปิดใช้จนกว่าจะ push ไปยัง GitHub repository ของคุณและเปิด Pages**

1. สร้าง GitHub repository ของคุณ แล้วนำไฟล์ทั้งหมดในโปรเจกต์ขึ้น branch `main`
2. Repository Settings > Pages > Source: GitHub Actions
3. Settings > Actions > General: อนุญาต workflow และ read/write contents ของ repository
4. ไป Actions > Hourly refresh and deploy > Run workflow เพื่อตรวจการทำงานครั้งแรก
5. Workflow ตรวจข้อมูลนาทีที่ 17 ของทุกชั่วโมงตาม UTC (ในไทยก็นาทีที่ 17 ทุกชั่วโมง) แล้วทดสอบ บันทึกข้อมูล และ deploy ผ่าน GitHub Pages

URL ที่ได้จะเป็น `https://USERNAME.github.io/REPOSITORY/` และรองรับ repository subpath แล้ว GitHub อาจเลื่อนเวลา scheduled run และบาง repository ที่ไม่มีกิจกรรมอาจถูกหยุด schedule ตามนโยบายแพลตฟอร์ม ตรวจในหน้า Actions หากขาดช่วง

ไม่ต้องเพิ่ม scraping API key ไม่มีการเก็บ token ใน source ใช้ GITHUB_TOKEN ของ workflow เท่านั้น นโยบายองค์กรหรือชนิดบัญชีอาจจำกัด Pages ของ private repo หากจะเปิดเป็น public ให้ตรวจความตั้งใจในการเผยแพร่ก่อน

**GitHub:** สร้าง repository ส่วนตัว `revv586/near-one-stays` แล้ว แยกขั้นตอนตรวจและบันทึกข้อมูลรายชั่วโมงออกจากการเผยแพร่ Pages ซึ่งถูกพักไว้ด้วย repository variable `NEARONE_PAGES_ENABLED` จนกว่า Pages พร้อมใช้งาน เว็บส่วนตัวบน Sites ยังไม่ได้ผูกกับข้อมูลที่ GitHub อัปเดตแบบอัตโนมัติ

## ขอบเขตตัวตรวจข้อมูล

```
npm run refresh
npm test
npm run build
```

- ตรวจเฉพาะหน้าเว็บสาธารณะที่เข้าถึงได้และ robots.txt อนุญาต ไม่ข้าม login, CAPTCHA หรือกลุ่มปิด ไม่ส่งข้อความหาเจ้าของ
- RentHub: ใช้ข้อมูล structured `shortTerm.oneMonth/threeMonth/sixMonth` เมื่อ flag ระบุสัญญาระยะสั้นจริงเท่านั้น ไม่เอาราคาคอลัมน์ monthly รายปีมาแทน
- คำบรรยาย เงินประกัน หรือเงื่อนไขเปลี่ยน จะตั้ง `needsReview` เพื่อให้ตรวจทาน ไม่สรุปราคาและห้องว่างจากข้อความเอง
- LivingInsider/Hongpak/ThaiApartment/PropertyHub: ตรวจ metadata เมื่อเข้าถึงได้ เก็บราคาและสัญญาที่ตรวจทานแล้วไว้ การเปลี่ยน layout อาจต้องเพิ่ม adapter
- HTTP error, robots ไม่อนุญาต, schema เปลี่ยน: เก็บข้อมูลเดิมพร้อมสถานะ error ไม่เปลี่ยนเป็น “เต็ม”
- ค้นหน้ารวม RentHub ทั้งประเภททั่วไป/สัญญาสั้น และ Hongpak รวม 21 หน้าใน 7 สถานีเป็นคิวเบาะแส ไม่ใส่เป็นห้องตรงเกณฑ์ทันที เพราะต้องตรวจเพศ ระยะเดิน สัญญา และวันว่าง
- PropertyHub, DDproperty, Hipflat, ZmyHome, Dot Property, Kaidee, ENNXO, CondoThai และ Facebook ไม่มีการรับรองว่าค้นได้ทุกประกาศ เพิ่ม URL สาธารณะที่ตรวจทานแล้วได้ ไม่อ้างสิทธิ์เข้าถึงกลุ่มปิด
- รายการโปรด/เปรียบเทียบไม่ได้ sync ข้ามเครื่อง หากล้าง browser storage จะหาย

## ขอบเขตการเผยแพร่

เว็บบน Sites ที่ส่งในแชทยังเป็นเว็บส่วนตัวของเจ้าของ การตั้ง GitHub Pages จะสร้าง URL ของ GitHub แยกต่างหาก การเปลี่ยนข้อมูลใน GitHub ไม่ได้ทำให้ Sites ถูกเผยแพร่ใหม่เอง จึงไม่แสดงว่าการอัปเดต Sites รายชั่วโมงทำงานแล้ว

การสร้าง repository และเปิด Pages ต้องใช้บัญชี GitHub ที่มีสิทธิ์ ตั้งค่า Pages > Source เป็น GitHub Actions แล้วตั้ง Actions variable `NEARONE_PAGES_ENABLED=true` จากนั้นตรวจ workflow ครั้งแรกจน deploy สำเร็จ ก่อนอ้างว่า CI/CD ทำงานจริง หาก repository ส่วนตัวใช้ Pages ไม่ได้ตามแพ็กเกจ GitHub ให้คงความเป็นส่วนตัวและเลือกวิธีโฮสต์ภายหลัง ไม่เปลี่ยนเป็นสาธารณะอัตโนมัติ

## โครงสร้าง

```
dist/index.html             หน้าเว็บหลัก + hash router
dist/assets/app.js           UI ภาษาไทยและ state ในเบราว์เซอร์
dist/assets/model.mjs        กรองราคา/สัญญา/สถานี
dist/assets/style.css        Responsive UI
dist/data/listings.json      ข้อมูลหลักและผลตรวจ
dist/data/sources.json       18 แหล่งค้นหาและขอบเขตการเข้าถึง
scripts/discovery-sources.json   21 หน้ารวมสำหรับค้นพบเบาะแส
scripts/refresh.py           ตัวตรวจต้นทางและคิวค้นพบ
scripts/serve.mjs            Local HTTP server
scripts/validate.mjs         ตรวจ schema และความถูกต้อง
tests/                       ทดสอบเงื่อนไขที่เสี่ยงแปลข้อมูลผิด
.github/workflows/           CI + hourly refresh + Pages deployment
```

รายละเอียดสัญญา ราคา และห้องว่างใช้ประกาศเป็นแหล่งอ้างอิง ไม่ใช่การรับรองจากเจ้าของที่พัก
